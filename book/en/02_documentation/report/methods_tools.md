# Methods, tools, and models

The DIA v2 guide groups here standards, references, methods, tools, models, prototypes and metrics {cite:p}`dia_documentacion_tfg_v2`. The goal is not to list everything installed, but to explain the technical approach and justify decisions that affect the result.

## Methods

Describe the technical methodology: unified process, agile development, iterative prototyping, experimental methodology, systematic review, user-centered design or another approach. If you rely on known concepts, cite them and summarize only what is needed.

The method should explain how the work moved from problem to solution:

- project phases;
- decision criteria;
- validation strategy;
- relation between methodology and planning.

## Tools

Group tools by function:

- **Implementation**: languages, frameworks, libraries, databases, APIs, cloud services, devices or models.
- **Methodology**: task management, version control, continuous integration, testing, design, prototyping or technical documentation.
- **TFG writing**: LaTeX, Markdown, Jupyter Book, bibliography managers, diagram tools or AI assistants when they materially influenced the work.

Do not explain standard tools if they add no value. Saying that a text editor was used is rarely relevant; explaining why a specific AI library, architecture or database was chosen is relevant.

## Models, prototypes and metrics

Include models when they are part of the work: AI, mathematical, industrial, electronic, simulation, data or decision models. If there are wireframes, mock-ups or navigation diagrams, they should justify design and user experience.

Metrics are useful when they help assess the result: performance, accuracy, test coverage, user satisfaction, execution time, resource use, accessibility or documentation quality. A metric without interpretation proves little; always pair it with a criterion.
