# The Report

The report is the document that the assessment committee should be able to read from start to finish in order to understand the TFG. It should not contain every technical detail, but it must contain the important decisions: what problem is addressed, why it matters, what has been built or studied, how it has been validated and what can be concluded.

The DIA v2 guide presents the report as the document that connects the rest of the TFG documentation and justifies the adopted solutions {cite:p}`dia_documentacion_tfg_v2`. That is the central idea: the report does not replace the annexes; it guides them. The reader should be able to follow the main reasoning without reading every detailed requirement, diagram or test log.

## What should accompany the report

Before the technical chapters, the documentation should include several formal elements:

- **Cover page**: clear title, author, defense date and supervisor or supervisors. The title should be meaningful and avoid unexplained acronyms.
- **Supervisor consent form**: include the current official model when the call or Department requires it.
- **Resumen and abstract**: self-contained synthesis in Spanish and English, usually between 200 and 500 words. It should include the problem, methodology, tools, results and conclusions.
- **Glossary**: useful when the report uses domain terms, non-standard abbreviations or acronyms.
- **Indexes**: report table of contents, annex index and tables/figures indexes when used.

Figures and tables need captions and textual references. External resources must be cited. Mandatory requirements should use clear obligation wording: "must", "shall" or equivalent. Optional improvements should be marked as desirable rather than compulsory.

## How to use the sections

The following sections should remain connected:

- Objectives explain what the TFG tries to achieve.
- Background justifies why the problem deserves attention.
- Methods, tools and models explain the approach.
- Requirements, constraints and scope define the limits.
- The proposed solution shows what has been produced.
- Management, testing and risks show control of the process.
- Conclusions return to the objectives and assess the result.

When an explanation becomes too detailed for the report, move it to an annex and leave a summary and cross-reference here.
