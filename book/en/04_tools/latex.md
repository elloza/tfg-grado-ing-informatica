## Starting templates in Overleaf

Public Overleaf templates can be useful as technical starting points for folder structure, LaTeX configuration, bibliography handling, and PDF layout {cite:p}`overleaf_templates_tfg_informatica`. They are not official USAL or DIA templates. When using an external template, adapt it to the current TFG rules, review its license, remove institutional text that does not apply, and cite the original template.

Examples worth reviewing include the University of Seville TFG template {cite:p}`overleaf_tfg_us_trinidad`, the ULL-ESIT-GII TFG report template {cite:p}`overleaf_tfg_ull_torres`, the University of Málaga TFG report template {cite:p}`overleaf_tfg_uma_benitez`, the University of Cádiz software-development TFG template {cite:p}`overleaf_tfg_uca_software`, and the UDIMA Computer Engineering TFG template {cite:p}`overleaf_tfg_udima_mataran`.

## Overleaf from VS Code

If you want to write in VS Code while keeping the project in Overleaf, the cleanest route is usually Overleaf's Git integration, which lets you clone the project, work locally, and synchronize changes with `pull` and `push` {cite:p}`overleaf_git_integration`. Another option is the community extension [Overleaf Workshop](https://marketplace.visualstudio.com/items?itemName=iamhyc.overleaf-workshop), which opens Overleaf/ShareLaTeX projects in VS Code and supports editing, compiling, previewing, and collaboration features {cite:p}`vscode_overleaf_workshop`.

Treat any extension-based workflow as an external tool: check authentication, permissions, project state, and conflicts before relying on it for final TFG work.
